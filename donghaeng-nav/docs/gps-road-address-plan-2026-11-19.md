# 저정밀 위치 표시와 도로명주소 선택 계획

2026-11-19 KST · `feature/cheongju-osco-demo` · Android 1.0.5 및 웹 기준

후속 결정에 따라 수신 오차 표시와 대중교통 결과의 내 위치 보기를 구현했다. 도로명주소 연동은 중단하고 개발 중 추가한 코드와 로컬 키 설정을 제거했다. 아래 주소 설계는 요청 당시의 기록이다.

버스나 지하철에서 오차가 큰 위치도 지도에서 볼 수 있게 한다. 위치가 끊긴 동안에는 마지막 수신 위치와 경과 시간을 보여 준다. 출발지와 도착지는 등록 장소, 도로명주소, 지도 핀 중에서 선택할 수 있게 한다.

## 1. 수신 오차가 큰 위치 표시

현재 지도 추적과 도보 안내는 같은 위치 품질 검사기를 사용한다. 오차가 50m를 넘으면 두 흐름 모두 새 좌표를 받아들이지 않는다. 자동 GPS 출발점은 25m 이하일 때만 선택되고, 도보 안내의 자동 진행 기준은 35m 이하다. Android 대중교통 결과는 정류장과 역의 승하차 순서를 보여 준다. [품질 검사](../dist/gps-quality.js) · [안내 정책](../dist/navigation-policy.js) · [대중교통 결과](../dist/transit-ui.js)

| 수신 상태 | 변경 후 지도와 동작 |
| --- | --- |
| 유효한 최신 위치와 기존 품질 검사 통과 | 현재 위치 표시를 갱신하고 기존 출발점 및 도보 안내 기준을 적용한다. |
| 유효한 최신 위치, 수신 오차 50m 초과 | 대략적인 위치와 실제 보고된 오차 반경을 그린다. `대략적인 위치 · 오차 약 280m`처럼 텍스트를 쓰고 점선으로도 구분한다. 수백 m나 수 km의 오차도 수치를 표시하며 지도를 자동 확대하지 않는다. |
| 유효하지만 위치가 갑자기 크게 바뀜 | 지도 표시에서만 연속 표본을 확인해 위치를 다시 잡는다. 차량 이동을 수용할 수 있도록 표시용 판정을 도보와 분리하고, 단발성 점프로 지도를 이동시키지 않는다. |
| 신호 지연 또는 끊김 | 마지막 수신 위치를 흐리게 표시하고 `마지막 위치 · 1분 전`처럼 경과 시간을 보여 준다. 첫 좌표가 없으면 수신 대기를 표시한다. |
| 위치 권한 거부 | 권한 상태와 주소·지도 선택을 표시한다. 측정을 중단하고 활성 위치 표시를 정리한다. |

- `gps-quality.js`의 좌표·시간 검증은 공유한다. `gps-tracker.js`에는 지도 표시용 상태를 추가한다. 표시 좌표, 원본 오차, GPS가 자동 안내에 사용할 수 있는 좌표를 구분한다. 도보 안내 중에도 대략적인 위치와 신호 상태를 보여 주되 자동 진행, 이탈 판단, 재탐색, 도착은 기존 기준에 따른다. 도보 안내와 지도 보기가 전환될 때 위치 구독이 중복되는지도 점검한다.
- 마지막 측정이 오래되면 계속 움직이는 것처럼 표시하지 않는다. 신호가 돌아오면 새 좌표로 갱신한다. 지도 드래그로 자동 따라가기가 꺼진 경우에는 **내 위치로**를 누르면 다시 맞춘다.
- 현재 위치를 출발지로 쓰려는 사용자는 오차가 커도 **이 위치로 핀 맞추기**를 열 수 있다. 대략적인 위치와 오차 범위를 먼저 보여 주고, 사용자가 실제 출발할 보행로에 핀을 옮겨 확정한다. 신호 복구가 이미 선택한 주소나 지도 핀을 덮어쓰지 않도록 한다.
- Android 대중교통 결과에 **내 위치 보기**를 연결한다. 선택한 노선과 예정 승하차 순서를 유지하며 위치를 함께 표시한다. 터널처럼 좌표가 없는 동안은 마지막 위치와 예정 순서를 보고 확인한다. 실시간 차량 위치, 역 통과, 승차·하차 자동 판정은 별도 데이터와 검증이 필요한 기능이다.

## 2. 도로명주소로 출발·도착 지정 초안

현재 양쪽 입력창은 서울·오스코 등록 장소 목록에서 이름과 주소 문자열을 찾는다. 일반 도로명주소의 좌표는 조회하지 않는다. [현재 장소 검색 코드](../dist/app.js) · [기존 출발지 검색 기록](origin-search-2026-11-14.md)

1. 기존 입력창에서 등록 장소를 바로 보여 주고, **도로명주소 검색**을 누르면 주소 서비스에 조회한다. 시·군·구, 도로명, 건물 본번·부번을 포함한 주소를 결과에 표시한다. 도로명만으로 후보가 많으면 도시나 건물번호를 추가하도록 안내한다. 모바일 질문창 안에서 결과를 읽고, 키보드로 검색과 선택을 할 수 있게 한다.
2. 행정안전부 주소정보 조회 API에서 주소 후보를 받고, 사용자가 선택하면 해당 주소의 행정구역코드·도로명코드·지하여부·건물번호로 좌표를 요청한다. 앱에서는 웹과 APK가 같은 서버 엔드포인트를 사용하도록 연결한다. 발급 조건, 운영 서버 호출 가능 여부, 각 API의 승인키와 제한은 연결 단계에서 실제로 확인한다. 승인키는 서버 환경변수에 저장하고 주소 조회에는 명시적으로 입력한 검색어만 보낸다. GPS 좌표와 이동 상태 문장은 주소 검색 요청에 포함하지 않는다. [주소 조회 API](https://www.data.go.kr/data/15057017/openapi.do) · [주소 좌표 조회 API](https://www.data.go.kr/data/15056663/openapi.do)
3. 공급자가 정의한 원본 좌표계와 X·Y 축 순서를 확인해 서버에서 WGS84로 변환한다. 서울과 청주의 공개 시설 주소를 기준으로 좌표 변환을 대조한 뒤 앱에 연결한다. 결과는 출처가 표시된 **주소 기준점**으로 지도에 띄우며, 필요하면 출발할 보행로 또는 이용할 출입구로 핀을 옮기게 한다. 주소가 검색되는 범위와 도보 경로 계산 범위는 화면에서 따로 안내한다. 청주오스코의 주소 위치 지정은 가능해져도 도보 계산 지원 여부는 기존 경로망 기준에 따른다.
4. 검색 결과 없음, 좌표 없음, 연결 실패를 구분한다. 요청 중 검색어를 바꾸거나 다른 위치를 고르면 이전 응답이 새 선택을 덮지 않게 한다. 연결이 끊겼을 때는 기존 등록 장소 검색과 지도 핀 선택을 사용할 수 있다.

## 검증 계획

1. **위치 표시**를 먼저 수정한다. 15m에서 80m·300m·2km로 오차가 커지는 모의 신호, 차량 속도, 단발성 위치 점프, 첫 좌표부터 저정밀인 경우, 터널 단절 후 복구, 권한 거부를 재현한다. 대략적인 위치가 표시되는 동안 도보 진행과 자동 도착이 발생하지 않는지 확인한다.
2. **주소 검색**을 연결한다. 서울·청주의 공개 주소로 출발지와 도착지 선택, 건물 부번, 이름이 비슷한 여러 주소, 잘못된 주소, 좌표 누락과 늦게 도착한 응답을 검증한다. 좌표 변환과 서울 도보 경로 계산을 확인하고, 청주에서는 주소 핀과 기존 지원 범위 안내를 확인한다.
3. **화면과 실기기**를 검증한다. 일반·밤하늘 테마와 모바일 세로·가로 화면에서 오차 표시와 검색 결과를 확인한다. 갤럭시 S22+에서 버스 주행, 지하철 지하 구간과 지상 복귀, 대략적인 위치 권한, 삼성 키보드를 실제로 검사한다. 웹 공개판의 도보 흐름과 Android 대중교통 후보 선택도 함께 확인한다.

이번 계획은 소스 동작과 공급자 공개 문서를 기준으로 작성했다. 실제 주소 API 응답의 좌표계와 운영 서버 연결, S22+의 이동 중 위치 수신은 구현 단계의 검증 항목이다.

## 구현 검사

- 독립 지도 추적과 도보 안내에서 표시 좌표와 진행 판정을 분리했다. 지도 오차 50m 초과는 대략적인 위치로 분류한다. 표시용 점프 판정은 최대 45m/s의 차량 이동을 수용하고, 한 번의 큰 점프에서 오차 반경 자체가 수 km라도 즉시 위치를 변경하지 않도록 했다. 수신이 15초 이상 갱신되지 않으면 마지막 위치와 경과 시간을 표시한다. 출발점 확정, 도보 진행, 재탐색과 도착은 각각 기존 품질 기준을 사용한다.
- 지도에서 **이 위치로 핀 맞추기**를 눌러 출발점을 직접 지정할 수 있다. 회복된 위치가 이미 지정한 출발점을 덮지 않도록 했다. Android 대중교통 결과에서 **내 위치 보기**를 눌러 선택한 노선과 승하차 순서를 유지한 채 위치를 볼 수 있다. 기기의 대략적인 위치 권한도 받는다.
- 모의 시험에서 버스 속도, 2km 오차, 위치 점프, 1분 신호 단절과 복귀, 직접 핀 지정, 안내 진행 보류를 확인했다. 웹 소스 및 단일 HTML, Android 모의 대중교통과 API 설정을 검사했다. S22+의 실제 버스·지하철 위치 수신과 현장 검증은 남아 있다. [위치 품질](gps-quality-results.json) · [화면 검사](gps-quality-ui-results.json) · [Android 모의 검사](android-demo-results.json)
