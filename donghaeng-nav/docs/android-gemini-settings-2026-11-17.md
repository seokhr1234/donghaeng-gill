# Android Gemini 키 입력·교통 키 상태 — 2026-11-17 KST

사용자가 APK의 키 적용 여부를 질문하고 Gemini 키 입력 방법을 요청했다. 후속으로 APK 게시 진행도 지시했다. 밤하늘 수정과 함께 최종 **1.0.4/versionCode5**에 반영하며, 처음 생성한 미게시1.0.4보다 이 후속 빌드가 최신이다.

## 사용 방법

1. APK 화면 위 **API 설정**을 연다.
2. **AI · Gemini → Gemini API 키 입력·변경**에서 Google AI Studio의 개인 키를 입력하고 저장한다. 입력은 Android 네이티브 암호 필드이며 웹 JS로 키 값을 반환하지 않는다.
3. **기기에 입력한 Gemini 키 적용 중**이 표시되면 길 찾기에서 사용한다. 이 표시는 저장 상태이며 실제 인증/할당량/모델 이용 성공 확인은 아니다.
4. **Gemini 기기 키 삭제 · 서버 사용**으로 개인 키를 지우면 기존 Vercel 서버 연결로 돌아간다. 개인 키를 입력하지 않아도 서버에 설정된 키를 사용할 수 있다. 이번 실제 `/api/status`는 `configured:true`, 모델 `gemini-3.5-flash-lite`였다. 실제 Google 호출 검증으로 확대하지 않는다.
5. **대중교통 · ODsay → 대중교통 키 입력·변경**에서 본인의 Android 키를 넣는다. 공개 배포판에는 고정 키를 내장하지 않으며 기기에 입력한 값만 사용한다. 과거 비공개 빌드를 사용하는 경우에만 내장 키 상태/복원을 표시한다.

기존 교통 키 입력창은 이미 키가 있어도 보안을 위해 빈칸으로 열렸다. 그 안내가 항상 입력을 요구했고, 빈칸 저장도 기존 키를 덮을 수 있어 혼동을 만들었다. 현재는 적용 상태를 설명하고 빈칸 저장을 거부해 기존 설정을 유지한다. 새 입력창에도 저장된 비밀 값을 미리 채우지 않는다.

## 통신·비밀 분리

- Gemini 개인 키는 Android의 앱 전용 SharedPreferences에 저장한다. 기존 `allowBackup:false`를 유지한다. 키 값은 JS·localStorage·Vercel·Git·로그로 반환하지 않는다. Native status는 설정 유무만 반환한다.
- 개인 키가 있으면 네이티브 HTTPS가 Google의 고정된 `generativelanguage.googleapis.com` 모델 경로에 `x-goog-api-key` 헤더로 요청한다. 키를 URL에 붙이지 않는다. 개인 키가 없으면 기존 서버 API를 사용한다.
- 문장 해석과 경로 비교는 기존 ConditionRequest/ConditionAI/RouteChoice 계약을 재사용한다. 상태 문장·동일 조건의 익명 수치 후보만 전송하며 좌표·목적지 이름·지도 도형을 자동 추가하지 않는다. 입력/응답 검증·취소·부정 표현·조건 보존을 유지한다.
- 인증/할당량/응답 형식 실패를 개인 키 사용 성공으로 표시하지 않는다. 실패 뒤 서버에 자동으로 한 번 더 유료 요청하지 않는다. 앱의 기존 기기 내 해석/알고리즘 대체 상태를 유지한다.
- 공개 APK에는 ODsay/Gemini 고정 키를 포함하지 않는다. ODsay와 개인 Gemini 키는 기기에서 입력한다. 서버 Gemini 키를 추출해 APK에 넣지 않는다. Gradle 기본값은 고정 키 제외이며 공개 검사는 로컬 실제 키가 모든APK항목에 없는지 확인한다.

사용자가 공개 상태/게시 보류 안내 후 APK 게시 진행을 요청했으나, 키 포함 공개 업로드는 아래 자동 승인 검토에서 거부됐다. **실제 공개 배포본은 ODsay/Gemini 고정 키가 없는 입력형 APK**다. 앞선 관리API403과 중간 키 포함 빌드 기록은 당시 상태로 보존한다.


## 공개 배포 게이트

사용자가 키 포함APK 게시를 요청했으나, 자동 승인 검토가 **공개 저장소에 자격 증명이 내장된 APK/tag/ZIP 업로드**를 자격 증명 노출을 이유로 거부했다. 이 작업은 실행되지 않았으며 새 태그/Release가 생성되지 않았다. 위의 게시 진행 지시는 허용을 뜻하는 최종 정책으로 취급하지 않는다. 검토 거부를 우회하지 않고, **고정 키가 없는 공개 APK**로 다시 빌드해 두 키의 네이티브 기기 입력 기능을 제공한다. Gemini 서버 기본 연결은 그대로다. 로컬 키 포함 미게시 빌드는공개파일과분리해보관하고 배포하지 않는다.
